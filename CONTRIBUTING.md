# Contributing to Mirage

Thanks for wanting to make Mirage better! Bug reports, colour schemes, translations and code are all welcome.
Questions and loose ideas are best started in [Discussions](https://github.com/Passimoritz/spicetify-mirage/discussions).

## 🛠 Setup

You need [Spicetify](https://spicetify.app) 2.40+ and Node.js 20.19 or newer.

```bash
git clone https://github.com/Passimoritz/spicetify-mirage
cd spicetify-mirage
npm install
```

Point Spicetify at your checkout instead of a copy, so every build is picked up directly:

```bash
# Windows (PowerShell, as admin or with developer mode):
#   New-Item -ItemType SymbolicLink -Path "$env:APPDATA\spicetify\Themes\Mirage" -Target "$PWD\Mirage"
# macOS / Linux:
ln -s "$PWD/Mirage" "$(dirname "$(spicetify -c)")/Themes/Mirage"

spicetify config current_theme Mirage color_scheme Mirage inject_css 1 replace_colors 1 inject_theme_js 1
spicetify apply
```

Day-to-day loop – two terminals:

```bash
npm run watch        # rebuilds Mirage/theme.js from src/ on every save
spicetify watch -s   # re-applies the theme and reloads Spotify when Mirage/ changes
```

Before you push:

```bash
npm run lint         # ESLint on src/, Stylelint on Mirage/user.css
npm run check        # rebuilds Mirage/theme.js and fails if the committed bundle is out of date
```

## 🗂 Project layout

| Path | What it is |
|---|---|
| `src/` | The theme script as ES modules (`src/main.js` is the entry point). **Edit here.** |
| `Mirage/theme.js` | The bundled script, generated by esbuild from `src/` (`npm run build`). Do not edit by hand – but **do commit it**: the Spicetify Marketplace loads this file directly from the repo. |
| `Mirage/user.css` | All styling. Plain CSS, linted with Stylelint. |
| `Mirage/color.ini` | The colour schemes (`Mirage`, `Obsidian`, `Sakura`, `Abyss`, `Ember`). |
| `overlay/` | The Mirage Overlay companion app (Electron). `cd overlay && npm install && npm start`. |
| `manifest.json` | Marketplace entry – CI checks that every file it references exists. |
| `assets/` | Screenshots and illustrations for the README. |

## 🎨 Adding a colour scheme

1. Open `Mirage/color.ini` and add a new section below the existing ones. It needs all 18 keys, as hex values without `#`:

   ```ini
   [Aurora]
   text               = F2FFFB
   subtext            = A9C9C0
   main               = 050B0A
   main-elevated      = 0F1A18
   highlight          = 172623
   highlight-elevated = 20332F
   sidebar            = 081110
   player             = 081110
   card               = 111D1B
   shadow             = 000000
   selected-row       = D6FFF4
   button             = 5CFFD2
   button-active      = 9DFFE4
   button-disabled    = 3A524C
   tab-active         = 1F3A34
   notification       = 2FB894
   notification-error = FF5C7A
   misc               = 7F9A93
   ```

2. Keep it dark: Mirage is a glass theme and draws light text on top of `main` / `card`. Check that `text` and `subtext` stay readable on `card` and `highlight`.
3. Try it with `spicetify config color_scheme Aurora && spicetify apply`, on a playlist, an album, an artist page and in immersive mode.
4. Add the name to the README scheme list (`README.md` and `README.de.md`) and, if you can, to `assets/schemes.svg`.

Note: only the `Mirage` scheme follows the album cover live; every other section is a fixed palette.

## 🌍 Improving a translation

All theme strings live in the `I18N` object in the i18n module (`src/i18n.js`). Each language is one object keyed by its code (`en`, `de`, `fr`, …):

- **Fix or complete a language:** compare it with `en` – every key that is missing falls back to English, so missing keys are exactly what needs translating.
- **Add a language:** copy the whole `en` block, give it the language code Spotify uses (for example `sv`, `cs`), translate the values and keep the keys unchanged.
- Keep texts short – they appear in a settings dialog and on small buttons.
- The overlay app has its own strings in `overlay/i18n.js`.

## 🌱 Good first issues

- Fill in missing keys in the shorter translations (for example `tr`, `ru`, `uk`, `ja`, `ko`, `zh`).
- Add a new colour scheme (see above).
- Fix a styling glitch on a page Mirage does not cover well yet – attach a before/after screenshot.
- Clean up the Stylelint warnings in `Mirage/user.css` (duplicate selectors that can be merged).
- Improve keyboard focus styles or contrast in a dialog.

Look for issues labelled [`good first issue`](https://github.com/Passimoritz/spicetify-mirage/labels/good%20first%20issue).

## ✍ Commit style

Short, imperative subject lines that say what the commit does – no trailing full stop:

```
Fix header colour block on album pages
Add Aurora colour scheme
Translate settings dialog to Polish
```

Add a body if the *why* is not obvious (for example which Spotify version changed a class name). One topic per commit; regenerate `Mirage/theme.js` in the same commit as the `src/` change it belongs to.

## ✅ Pull request checklist

- [ ] `npm run lint` passes
- [ ] `npm run check` passes (the committed `Mirage/theme.js` matches `src/`)
- [ ] Tested on **Spotify X.Y.Z** with **Spicetify X.Y.Z** (please write the versions in the PR)
- [ ] Checked with calm mode / *reduce motion* on, if the change touches animations
- [ ] Screenshots attached for visual changes (personal data pixelated)
- [ ] `README.md` **and** `README.de.md` updated if user-visible behaviour changed
- [ ] User-visible changes described in the PR text (the maintainer collects them in `CHANGELOG.md`)
